# Test Executor на Си

## Зачем

Test Executor запускает тестируемый процесс, ограничивая его,
следя за процессом с помощью strace.
strace с правильными фильтрами умеет
следить за вызовом системных вызовов, а также фейлить их.

Почему на Си - чтобы показать один из самых низкоуровневых
способов работы с cgroup / namespace.
В Linux существуют утилиты unshare и т.д. для этих действий
(для некоторых нужно пакет поставить, например util-linux).
Однако, они могут выполнять лишние действия, или их может не хватить.
В связи с этим нужно уметь выполнять те же действия в Си.
Реальная реализация executor может по ситуации или использовать
системные вызовы, или просто вызывать эти утилиты.

## Текущее поведение при запуске

Комментарии по коду поясняют необычные особенности
работы cgroup / namespace (почему форкаемся и т.д.)

При запуске происходит следующее:
1. Создает новую cgroup
2. Добавляет в cgroup ограничения
3. Запускает новый процесс, делает его НЕ своим child'ом с помощью двойного fork
(Этот процесс будет дальше конфигурироваться, дальше форкнется,
и форк заменится на тестируемую программу (UUT, Unit Under Test)
с помощью системного вызова вида exec)
4. Внутри child:
   1. Процесс вводится в cgroup
   2. Процесс вводится в нужные namespace'ы.
   Логика ввода в namespace разделена на части не просто так,
   если выполнять некоторые вызовы без fork, то оно не будет правильно работать.
   Процесс вводится в самодельный контейнер с mount OverlayFS.
   Создается mount tempfs для ограничения по размеру файловой системой
   (но есть и другие способы ограничения именно размера доступного дискового пространства).
5. Вне child происходит слежка за процессом child.
После запуска uut подключается strace и выводит в файл вывод strace.
Программа ждет завершения uut

## Чего не хватает

Следить за конкретными файлами stdin/stdout/stderr -
можно через чтение `/proc/<pid>/fd/<fdid>` - **есть пример отдельный**

Больше скриптов strace для разных вариантов слежки - **есть пример отдельный**

Подмена системных вызовов на кастомные - **есть пример только на изменение возврата системных вызовов / полный фейл системных вызовов**

Запуск первоначально остановленного uut - **есть в примерах запуск с raise(SIGSTOP) - так можно**

Test Executor должен быть разделен на утилиты (**он не разделен**),
каждая из которых должна выполнять свое действие,
чтобы было легко использовать его из скрипта.

## Сборка

```bash
# Из root директории
mkdir build
cd build
cmake ..
make
```

## Преднастройка

Распаковать uut-folder.tar в build/uut-folder - это используется для OverlayFS

## Запуск

```bash
sudo ./ostest
```
