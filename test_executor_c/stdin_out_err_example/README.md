### Замена stdin/stdout/stderr

### Проблема

Когда просто запускаем в терминале, наш stdout - это PTY
Там используется буферизация по строкам. stderr не буферизируется по строкам.
stdin - тоже PTY (а если был detatch процесса через &, то /dev/null),
чтобы что-то отправить, в stdin нужно добавлять лишние управляющие символы для PTY.
Если приложение крашится, то может потеряться вывод stdout, который не успел отправиться. 

### Решение

Меняем stdin на pipe, stdout/stderr на файлы.
Читаем вывод приложения из файлов, пишем в пайп stdin.
Всегда актуальные stdin/stdout/stderr можно найти в procfs:
- /proc/{pid}/fd/0 - stdin
- /proc/{pid}/fd/1 - stdout
- /proc/{pid}/fd/2 - stderr

Через readlink можно найти куда эти файлы указывают.

### Важно: если вывод не в PTY, а в обычный файл / pipe, то идет буферизация не по строкам, а до 4к символов
Если создали новый stdout, то printf не будет писать ничего в файл, пока не наберет 4к символов.
Если произойдет краш, то потеряется все, что должно было записаться в stdout.

Можно использовать утилиту stdbuf для починки этого.
Можно в исходник посмотреть как работает,
если не получится утилиту использовать по каким-то причинам.
Используется механизм LD_PRELOAD.
Альтернативно можно добавить в исходники uut функцию setvbuf().
